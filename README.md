# 案板错用识别研究原型

本地 YOLO 检测、冻结 Qwen3-VL 4B 复核、现场用途规则和视频证据导出。尚不能可靠自动认定真实案板错用。

2026-10-29进展：完成36帧批次、43候选复核、4来源36裁剪，以及整视频留出的小型分类层训练。跨源仍有8个错误，实验分类层未采用；未微调大模型。详情见 reports/food_presence_head_v1/报告.md。

仓库仅含代码、文字报告、交接文档和模型路径清单；视频、原图、数据集、环境和权重留本机。报告中的本机配套文件不一定随仓库发布。

## 2026-11-06 进展：板存在性 48/48，无板 111 帧误报 2 次

**能力现状（都是开发集，不是准确率）**

| 能力 | 现状 | 证据 |
| --- | --- | --- |
| 有没有案板 | 48 帧有板全部命中；111 帧无板中误报 2 次（约 1.8%） | 九批新整源（v1–v8），见 `新整源v*_*.md`、`盲标更正与累计证据报告.md` |
| 板在哪里 | 模型框仅 16/48 可用（33%）；中景 75%、特写约 30% | `新整源v5_中景后厨报告.md`、`框细化探针_负结果报告.md` |
| 板上是什么 | 检测器真实后厨召回仍低，默认模型未替换 | `第29次补玉米训练结果报告.md`、`接棒第30次_上游人体屏蔽探针报告.md` |

**入口与工具**

- `review_combined.py`：VLM 判存在性 + YOLO 给食物框 + 位置护栏；`--board-box/--board-json` 人工框优先
- `review_board_only.py`：单问案板（49/49 可解析）
- `set_board_box.py` / `audit_board_boxes.py` / `verify_board_positives.py`：人工框定、框内材质回查、正例复核卡
- `board_annotation_queue.py` / `build_board_seg_dataset.py`：标注队列与 YOLO bbox 数据集（按来源视频组切分）
- `check_state_sync.py`：两条线并行时的产物对账

**已排除的方向（都有报告，避免重复投入）**

| 尝试 | 结果 |
| --- | --- |
| 加大 max_new_tokens（300→600） | 失败率不变 |
| 强化输出契约提示词 | 判断漂移 38.8%，判据不成立 |
| 拆成三个单任务提问 | 单问案板 49/49，三段合并有效率仅 77.6% |
| 2×2 分块放大 | 只把炒锅误判成板，未找回真板 |
| 裁到粗框再问 | 7 帧过粗仅 1 帧改善 |
| 经典几何找板面 | 6 帧仅 1 帧正确 |
| 上游整体屏蔽人体 | 会把"手里拿的食物"一起挡掉 |

**标注与自查**

- 人工板框 27 个，`datasets/board_seg_v4`：train 24 / val 3（val 按整段视频留出）
- 单人目检累计 **8 次更正**（5 次漏看板、1 次把炒锅当板、2 次把编织竹席当板）
- 固定规则：分歧帧必须放大看图；每次扩标后跑一次 `audit_board_boxes.py`
- 判定口径：`标注规范_砧板定义.md`

**仍未解决**：真实后厨食材召回、板面位置的规模化定位、人体误检、跨更多独立场景验证。

- 新增商业厨房多视角和B站切配片段研究，已完成局部食材标注、固定阈值选权重及混训实验。公开视频的可访问性不等于创作者授予训练或发布许可。
- 最近发现切碎红椒常被误认成肉。新增两段对照视频，人工复核16张图、26个食材粗区域框，均由助手单评审，非专家标注。

## 运行入口

- `review_app.py`：本地图片与逐板用途人工复核。
- `check_board_misuse.py`、`batch_check_images.py`：单图/批量疑似冲突提示。
- `import_video.py`、`probe_canteen2.py`：本地视频抽帧和检测；检测框不是训练真值。
- `prepare_manual_dataset.py`、`run_experiment.py`：数据审计、来源组划分和实验管线。
- `run_redveg_contrast_trial.py`：最新失败实验的预锁训练方案；依赖本机数据和已有中间文件，不能只克隆代码就复现数据部分。

模型配置和SHA见`model_manifest.json`。仓库不含权重，需另行取得有权使用的权重，按对应路径放置后运行`python configure_local_models.py`。部分研究脚本仍有D盘路径，换机器需要调整；本次发布没有改动原电脑的数据或模型。

Python 3.13及原Windows/CUDA依赖见`requirements-lock.txt`；视频下载依赖另见`requirements-video.txt`。没有跨平台一键安装保证。下载视频只取视频轨，抽帧使用OpenCV，不要求本地ffmpeg。

本次同步核对的测试：

```console
python -m unittest test_misuse_rules test_operational_selection test_manual_dataset test_annotation_review test_experiment_pipeline test_review_sessions
```

软件测试与模型准确率分开记录。用途规则必须来自现场规定；演示规则保留`demo_not_site_policy=true`，不能据此给实际厨房判罚。

## 数据与发布范围

本仓库同步代码、文字报告、交接和模型路径/SHA清单；**不含原图、视频、数据集、逐图私人复核数据、训练缓存、原始日志或权重**。新B站素材及商业厨房数据的原始文件、模型均留本机。第三方数据、基础模型和依赖各有独立条款，本仓库不替它们授予许可。

报告中的本机路径、配套图片和实验JSON可能不在仓库；不要把缺少这些数据的源码快照当作完整可运行模型包。后续重点为细碎红椒/肉末对照、标注一致性、保留旧能力的受控实验，以及真正独立操作/厨房的评估。
